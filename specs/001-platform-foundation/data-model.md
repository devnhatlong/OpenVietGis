# Data Model: Platform Foundation

**Feature**: 001-platform-foundation  
**Date**: 2026-11-17

Spec 001 intentionally defines only a disposable foundation entity. It MUST NOT define the final
Organization, Workspace, Project, Layer, identity, tenant, or spatial feature models.

## FoundationSampleRecord

Purpose: prove the supported persistence path end to end without creating future business
semantics.

### Fields

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `id` | UUID | yes | Generated by the application; stable public identifier |
| `label` | short text | yes | Trimmed; 1-120 Unicode characters |
| `created_at` | timestamp with timezone | yes | Set when persisted |
| `updated_at` | timestamp with timezone | yes | Equal to created_at for Spec 001 because update is not exposed |

### Relationships

None.

### Ownership and tenancy

This record is development/foundation proof data only and is not tenant-owned business data.
Therefore Spec 001 does not invent an Organization owner before Spec 002 defines tenancy semantics.

The table/schema MUST be clearly marked as foundation/test runway data so it can be removed when
real product entities replace the vertical slice.

### State transitions

```text
Not present
   |
   | create(label)
   v
Persisted
   |
   | read(id)
   v
Persisted
```

Update, delete, soft-delete, audit history, ChangeSet participation, and tenant ownership are
intentionally outside Spec 001 because this record is not material user/business data.

### Validation

- Reject blank labels after trimming.
- Reject labels over 120 characters.
- Reject malformed identifiers on lookup.
- A missing record returns a normal not-found outcome and does not create a placeholder.

## ArchitectureDecision

Architecture decisions already exist as versioned Markdown ADRs rather than relational data.

Required document attributes:
- sequential ADR number;
- title;
- status;
- date;
- context;
- decision;
- consequences.

State lifecycle:

```text
Proposed -> Accepted -> Superseded
                   \-> Deprecated
```

A superseding ADR references the decision it replaces; old ADRs remain in history.

## ArchitectureBoundary

Architecture boundaries are repository rules rather than runtime rows.

Initial critical rule:
- code owned by the platform/Core MUST NOT import or depend on a vertical domain module.

The automated checker reports:
- rule id/name;
- offending source path;
- offending target/import;
- pass/fail.

## FoundationValidationResult

The baseline validation result is ephemeral CI/developer output, not business data.

Required categories:
- static/type/lint quality;
- unit tests;
- architecture rules;
- database integration/migration;
- browser vertical slice.

A run is successful only when every mandatory category passes.
