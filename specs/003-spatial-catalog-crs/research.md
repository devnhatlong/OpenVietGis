# R003 implementation research and decisions

**Date**: 2026-11-18. **Basis**: verified R002 main 64f00e67c18c87ddd16e76498e100c30ddfad455, accepted ADRs, [CRS matrix](crs-support-matrix.md), [control evidence](vn2000-control-evidence.md), [fixture profile](reference-fixture-profile.md). Evidence here is design input, not proof of runtime acceptance.

| Decision | Rationale | Rejected alternatives |
| --- | --- | --- |
| Native PostGIS XY geometry + explicit metadata | Preserve source truth and future R005 provenance; transform only the returned copy. | Normalize all storage to 4326, infer SRID, rewrite source on reading. |
| Explicit finite directed edge registry | Definition support is not transformation support; direct operations must be independently validated. | Arbitrary EPSG transforms, automatic chaining, generic VN-2000 string. |
| Trusted platform reference registry, project-scoped materialization | Deterministic pre-established data selection; isolate every registered source's rows with RLS. Materialize a reference source once per Project/key, not per Layer, atomically. | File upload, user connection, global unrestricted feature table or per-Layer duplication. |
| Stable logical field IDs and typed attributes | Avoid exposing physical schema or tying IDs to display order; preserve exact decimal/null semantics. | Return arbitrary untyped columns, stringify all values. |
| Four revision domains | Metadata rename does not invalidate feature pages; content or schema changes do. Layer changes independently. | Timestamp-only revision, single global token, reconstructing incompatible pins silently. |
| Keyset pagination + scoped pinned continuation | Deterministic ordered bounded feature reads and retry-safe detail; reject stale rather than serve mixed data. | Offset pagination or unbounded queries. |
| R002 authorization and new project-specific RLS | Existing org/actor context and current grants retained; project isolation independently enforced for new rows. | RLS bypass, browser enforcement, org-only project filtering. |
| Transactional audit + safe revision evidence | Track actual changed metadata state with actor/time; same commit as mutation, no secrets. | Audit after commit, destructive retirement, log raw request bodies. |

## Coordinate validation and operations

Public arrays are X,Y only. Geographic X longitude, Y latitude (degrees); projected X easting, Y northing (metres). Native EPSG axis order is separate metadata. API envelope is SpatialGeometry, not RFC 7946 GeoJSON for arbitrary CRS.

Supported CRS 4326, 3857, 4756, 5899; identities allowed only for supported, validated native sources. 3405/3406 are definition-only, not valid ready/read sources in this first slice. All eight direct edges exactly as recorded in the matrix. No direct 3857 ↔ 4756/5899 and no automatic intermediate transforms. Reject unknown/custom CRS, non-finite, unsupported family/dimension, known contradictory evidence. For 4326/4756 enforce longitude ±180 and latitude ±90. For 3857 enforce latitude ±85.0511287798066 on forward request, projected x/y bounds ±π×6378137, no clamp. Verified explicit Web Mercator XY pipeline `+proj=pipeline +step +proj=unitconvert +xy_in=deg +xy_out=rad +step +proj=webmerc +ellps=WGS84` (forward/inverse explicit functions); allow 1e-6 m floating-point tolerance for transformed output validation at the exact boundary, not input clipping. Independent analytic Pseudo-Mercator expected values from x=Rλ, y=R ln(tan(π/4+φ/2)) and inverse; tolerance 0.001 m projected / 1e-8 degree geographic (floating-point acceptance, not survey accuracy).

VN-2000 applicability is restricted to trusted Quang Ninh reference fixture provenance and finite XY vertices inside the following closed product rectangles in longitude/latitude degrees: 4756↔4326 [106.88,108.07] × [20.70,21.42]; all 5899 edges [107.15,107.18] × [20.70,20.73], testing projected coordinates via approved inverse projection to 4756. Check source and target vertices. These rectangles derive from the observed published control extents; they are product guard rails, not official boundaries nor accuracy claims over all positions. The independent controls include port-water and anchorage coordinates, whereas EPSG 6960 specifies Vietnam onshore; R003 validates these reference fixtures only, not an extension of EPSG scope. Frozen published DMS targets and source coordinates are in the control evidence; parse them independently for acceptance. Check all vertices before transformation and output domains afterward; no fallback or implicit clipping. Geographic control pairs ≤3 m; projected triple checks ≤1 m in both directions using published targets as inverse inputs. Research executed explicit PostGIS pipelines in read-only SELECTs against all independent controls. Use ST_TransformPipeline(geometry, 'urn:ogc:def:coordinateOperation:EPSG::6960', 4326) and ST_InverseTransformPipeline(..., 4756). Fixed TM-3 XY pipeline: `+proj=pipeline +step +proj=unitconvert +xy_in=deg +xy_out=rad +step +proj=tmerc +lat_0=0 +lon_0=107.75 +k=0.9999 +x_0=500000 +y_0=0 +ellps=WGS84` (forward 4756→5899, inverse 5899→4756). The two explicitly approved composite 5899↔4326 directions are fixed combinations of those exact steps, not user-selectable graph chaining. Research observed 1.212677–1.556287 m for the five geographic pairs, and 0.051604–0.189434 m across all 16 projected-control directions. Reproduce these independently in runtime acceptance; geographic comparisons are geodesic distances within the same datum, projected 5899 comparisons Euclidean metres. Use fixed assets and PROJ_NETWORK=OFF; explicit operation selection rather than automatic fallback. Research runtime reports PostGIS 3.7.0/PG18/PROJ9.9.0 with NETWORK_ENABLED=OFF and ST_TransformPipeline(geometry,text,integer)/ST_InverseTransformPipeline available. Measured image digest: postgis/postgis@sha256:fe440a27c6567aefa932e988962e5827bb2c29e4b97dac2ca5268f5eafe10262.

## Security and consistency

R002 routes resolve actor and require current tenant access before repository calls. For writes lock org first, then project, source, Layer consistent order; re-check actor, credential, grant, project state and expected revisions in transaction. Existing org/actor GUCs remain. Add project GUC for spatial access only, set locally after scoped authorization; composite keys enforce same organization/project in Layer→source and features/evidence→resource. Apply forced RLS to new tenant-sensitive tables and test restricted role with missing and wrong scope, pooling, direct-ID substitution. A caller authorized across two Projects still cannot cross-link. Read pages/detail must use one consistent source snapshot or a source lock sufficient to prove pins match actual values; no partial results. Careful lock ordering with source retirement and Layer creation.

## Fixture and acceptance design

Versioned deterministic primary sources: 4,000 points, 3,000 lines, 3,000 polygons; stable canonical IDs and independent expected values. Positive projected/VN-2000 native fixtures and separate negatives: empty, unknown CRS, contradictory declaration, axis mismatch demonstrable by domain/evidence, unsupported dimensions/family, null geometry, invalid geometry, outside supported region/edge, stale revisions, unauthorized actor. No blanket claim that ambiguous coordinates can be detected. Source registry validation and database constraints must not silently coerce.

Benchmark restricted-role HTTP requests with RLS active, after warm-up ≥100 samples each catalog list/detail and page100; distinguish native/transformed. Record runtime versions/image digest, profile revision, environment, sample counts, p50/p95/max, selected operation; acceptance thresholds from SC-007. CI regression plus agreed local environment evidence. No benchmark result claimed here.

## Remaining prerequisite to implementation

Independent review of exact source-control numeric fixtures and regional applicability, data model, OpenAPI, constraints and task trace. Any unverified control explicitly blocks advertising its edge; do not reduce acceptance or invent results. R002 external-release SC-013 stays deferred only for internal integration.
